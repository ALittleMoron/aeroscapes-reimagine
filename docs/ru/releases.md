Релиз Aeroscapes Reimagine фиксирует законченный объём изменений сборки и исходный код, из которого получен её архив. Номер имеет вид **`мажорная.минорная.патч`**, например `0.1.1`. Эти три части описывают масштаб завершённой работы.

## Как читать номер

| Часть    | Что фиксирует                                  | Пример  |
| -------- | ---------------------------------------------- | ------- |
| Мажорная | Большой этап развития всей сборки              | `1.0.0` |
| Минорная | Завершение согласованного направления или цели | `0.2.0` |
| Патч     | Очередную порцию добавлений и доработок        | `0.1.1` |

### Мажорная версия: большой законченный этап

Мажорный номер меняется, когда сборка достигает новой крупной цели. Сам по себе такой переход **не означает breaking changes** — обязательной несовместимости с предыдущим выпуском. Он обозначает, какой этап проекта завершён.

Крупные цели проекта:

| Рубеж   | Результат                                                                                                                                                                                                      |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `1.0.0` | Полный согласованный основной состав: необходимые крупные моды и доработки реализованы и проверены вместе.                                                                                                     |
| `2.0.0` | Тесная интеграция систем: например, магические инструменты помогают осваивать технику, а занятия разных направлений дополняют друг друга. Дополнительные квесты или квестовая линия могут объяснять эти связи. |

По мере развития проекта новые крупные цели получат следующие мажорные рубежи — `3.0.0` и далее. Их содержание определяется вместе с самими целями.

### Минорная версия: завершённая цель разработки

Минорная версия задаёт цель: к этому номеру согласованное направление сборки должно быть закончено. `0.1.0` зафиксировала исходную основу: островной мир, [Create](https://modrinth.com/mod/create) и [Aeronautics](https://modrinth.com/mod/create-aeronautics), базовую оптимизацию и удобства игры.

Основные этапы развития:

| Рубеж    | Направление                                                                                               |
| -------- | --------------------------------------------------------------------------------------------------------- |
| `0.2.0`  | Графика, звук, погода и анимации.                                                                         |
| `0.3.0`  | Повседневные удобства: инвентарь, рецепты, управление и работа с деревьями.                               |
| `0.4.0`  | Исследование островов, местная природа, находки и подготовка экспедиций.                                  |
| `0.5.0`  | Первый набор магии, качество экипировки и случайная перековка.                                            |
| `0.6.0`  | Инженерное расширение: обработка материалов, топливо, литейное дело, управление механизмами и артиллерия. |
| `0.7.0`  | Персонаж: расы, классы, профессии и развитие через занятия.                                               |
| `0.8.0`  | География островов, распределение ресурсов и маршруты экспедиций.                                         |
| `0.9.0`  | Расширенное снаряжение, мастерство и поздние специализации персонажа.                                     |
| `0.10.0` | Детальное строительство, сезоны и мирный быт.                                                             |
| `0.11.0` | Новые места, существа и занятия в Незере.                                                                 |
| `0.12.0` | Повседневные поручения NPC с отслеживанием и наградами.                                                   |
| `0.13.0` | Новые места, встречи и находки в Крае.                                                                    |
| `0.14.0` | Развивающиеся поселения, жизнь жителей, отношения и снабжение.                                            |
| `1.0.0`  | Основные системы сборки работают вместе.                                                                  |

Расы, классы и профессии появятся раньше подклассов. Подклассы тоже входят в план до `1.0.0`; их можно выделить в отдельный этап. Магия должна предлагать занятия и в бою, и в быту.

Порядок и наполнение могут уточняться по мере выбора содержимого. Этапы собираются небольшими патчами; финальная минорная версия фиксирует завершение выбранной цели и может состоять преимущественно из исправлений.

### Патч: очередные добавления и исправления

Патчи могут содержать новые моды, ресурспаки, настройки, совместимость и исправления. Последняя цифра не ограничивает выпуск только исправлением ошибок.

Пример последовательности: после `0.1.0` первая волна анимаций и ресурспаков может получить номер `0.1.1`, а следующая доработка — `0.1.2`. Каждая группа сохраняет свой номер при подготовке и включении в `main`. Отдельная группа после этого получает следующий патч, даже если публикация предыдущей завершилась ошибкой. Новые локальные сборки или подготовительные коммиты сами по себе номер не повышают.

## Готовность выпуска и совместимость

Публичные выпуски используют обычные числовые версии, без альфа-, бета- и тестовых суффиксов. Каждый из них фиксирует законченный и принятый объём работ. У версий `0.x.y` тоже есть собственный согласованный объём, хотя весь замысел сборки продолжает развиваться.

Совместимость сохранений зависит от конкретных изменений, а не от того, какая цифра увеличилась. Условия обновления указываются в описании выпуска; практические правила работы с мирами находятся в разделе [сохранений](../known-issues/#сохранения).

## Как изменения становятся релизом

1. Изменения сборки собираются в **один итоговый PR или push в `main`**. Внутри него может быть несколько подготовительных коммитов; отдельные промежуточные коммиты одного push не создают собственных версий.
2. Версия задаётся в `pack/pack.toml`. В истории изменений на английском и русском есть одна соответствующая секция, например `## 0.1.1`, с фактическими изменениями этого выпуска.
3. Номер входит в заголовок PR и в первую строку итогового коммита, попадающего в `main`: например, `feat: [0.1.1] animations and foliage`. При squash или merge итоговый заголовок тоже должен сохранить номер.
4. CI проверяет исходники и экспорт. Для новой версии он также проверяет номер в итоговом заголовке и обе секции истории изменений. Только успешный push в `main` передаёт проверенный архив на публикацию.
5. Автоматизация связывает тег `v0.1.1` с точным SHA итогового коммита и публикует проверенный `.mrpack` с контрольной суммой. Текст изменений берётся из секции этой версии в том же снимке исходников. Подготовительные коммиты могут быть перечислены как история работы, но сам выпуск относится к одному проверенному состоянию сборки.

Документация сайта и инфраструктура, сохраняющие содержимое экспортируемой сборки, могут меняться без новой версии модпака. CI устанавливает это сравнением содержимого архива с уже выпущенной версией; имя файла или путь изменённого исходника не заменяют такое сравнение.

## Если в заголовке пропущен номер

В PR достаточно исправить название: изменение заголовка повторно запускает CI. Если ошибка уже попала в `main`, проверка остановит публикацию. Её можно исправить следующим обычным коммитом с правильным номером в заголовке. Восстановление публикации этой группы сохраняет её номер: ошибка публикации не отменяет уже включённую в `main` версию.

После публикации содержимое версии неизменно. Для новых изменений нужен следующий номер; тег, архив и контрольная сумма позволяют однозначно найти исходный выпуск независимо от формулировок в истории Git.
